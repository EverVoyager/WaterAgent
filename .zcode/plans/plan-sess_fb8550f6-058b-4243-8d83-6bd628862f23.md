# 五类记忆架构重构方案（v2：对齐 Claude Code / Codex 双层记忆模式）

## 总体架构

| 记忆类型 | 承载 | 对标 |
|---|---|---|
| 1. 会话记忆 | `chat_sessions/chat_messages` + `context_compact.py`（现状保留） | 会话上下文 + compact |
| 2. 长期记忆 | **双层文件**：`MEMORY.md`（用户权威，Agent 只读）+ `memory/` 目录（Agent 自动记忆：`memory/MEMORY.md` 索引 + `memory/<topic>.md` 主题文件） | Claude Code CLAUDE.md + auto-memory 目录 / Codex AGENTS.md + Memories |
| 3. 语义记忆 | 新表 `agent_semantic` + Qdrant `agent_semantic_vec` | Codex project facts（服务化增强版） |
| 4. 情景记忆 | 新表 `agent_episodes` + Qdrant `agent_episodes_vec` | （标杆无，本项目特色） |
| 5. 程序记忆 | 新表 `agent_procedures` + Qdrant `agent_procedures_vec`，可晋升候选 Skill | Codex feedback rules（服务化增强版） |

旧表处置：`agent_memories`、`agent_skills`（自动习得表）废弃；`agent_reflections` 保留为审计；`skills`（人工配置）保留。

## 一、长期记忆：双层文件（v2 核心修正）

### 第一层：`MEMORY.md`（项目根，用户权威手册，Agent 只读）

```markdown
# Agent 记忆手册（人工维护，Agent 只读注入）
## 业务背景
## 预警规则约定
## 回答风格要求
```

Agent 永不写入此文件；用户手动编辑；git 跟踪。

### 第二层：`memory/` 目录（Agent 自动记忆，Claude Code auto-memory 模式）

```
memory/
├── MEMORY.md          # 索引：主题清单 + 每主题一句话摘要（Agent 维护）
├── user-prefs.md      # 主题文件：用户偏好与纠正
├── domain-facts.md    # 领域事实
├── constraints.md     # 约束与习惯
└── <auto-topic>.md    # 反思 LLM 自由命名的新主题
```

**新模块 `agent/memory/longterm.py`**：
- `load_longterm_memory() -> str`：拼接 MEMORY.md（用户层）+ memory/MEMORY.md 索引 + 全部主题文件；mtime 缓存；总长上限 6000 字（超出截断并在索引层标注）
- `apply_longterm_edits(edits) -> None`：执行反思编辑 `[{topic, action: append|update|create, content}]`——只允许写 `memory/` 目录：append 追加到主题文件尾部、update 整文件替换、create 新主题文件并更新索引；**路径校验拒绝逃逸 memory/ 目录**（防 `../` 注入写任意文件）；`threading.Lock` + 原子写（tmp + rename）
- 不依赖 MySQL，独立可用

### 注入（三处 system prompt 常驻）

planner（第 1 轮）/ direct_chat / synthesizer 追加：

```
=== 长期记忆 ===
【手册（用户设定）】{MEMORY.md 内容}
【Agent 记忆索引】{memory/MEMORY.md}
{各主题文件内容}
=== 长期记忆结束 ===
```

标注来源层级（用户设定 vs Agent 积累），冲突时用户层优先——对齐 CLAUDE.md 优先级语义。

### Docker

backend 卷挂载 `- ../MEMORY.md:/app/MEMORY.md` 与 `- ../memory:/app/memory`。

## 二、语义记忆：agent_semantic（不变，v1 方案）

Schema：`id / title(256) / content TEXT / source(reflection|curator|manual) / tags / hit_count / created_at / updated_at`。
模块 `semantic_store.py`：CRUD + `search_semantic(query, top_k)`（Qdrant `agent_semantic_vec`，不可用降级时间序）。
注入：synthesizer「领域知识」段 top-3（向量命中才注入）。

## 三、情景记忆：agent_episodes（不变，v1 方案）

Schema：`id / happened_at / event_summary(512) / resolution TEXT / outcome(success|failure|partial) / query_summary(512) / tool_calls_json / tags / created_at`。
模块 `episode_store.py`：`add / search_episodes(query, top_k)`（向量）/ list / delete。
注入：planner 第 1 轮「历史类似情形」top-2。旧 TOOL_FAILURE 并入（failure episode + resolution）。

## 四、程序记忆：agent_procedures（不变，v1 方案）

Schema：`id / name(128) / applicability TEXT / steps_json / tool_sequence_json / source(reflection|curator|manual) / use_count / success_count / refined_count / status(active|promoted|deprecated) / created_at / updated_at`。
模块 `procedure_store.py`：CRUD + 向量检索 + `record_procedure_use` + `promote_to_skill`（渲染 SkillCreate：description=applicability、instructions=steps 序号化、tool_names=序列去重、**enabled=false 人工确认**，成功后 status=promoted）。
注入：planner「推荐方法」top-2。

## 五、反思循环改造（新增敏感信息红线）

**REFLECTION_SYSTEM_PROMPT 输出 schema**：

```json
{
  "reflection": "一句话总结",
  "longterm_edits": [{"topic": "user-prefs", "action": "append|update|create", "content": "...", "reason": "..."}],
  "semantic_memories": [{"title": "...", "content": "...", "tags": []}],
  "episode": {"event_summary": "...", "resolution": "...", "outcome": "success|failure|partial"},
  "procedure": {"worthy": true, "name": "...", "applicability": "...", "steps": [...], "tool_sequence": [...]},
  "demote": {"semantic_ids": [], "procedure_ids": []}
}
```

**写入闸三道**（v2 强化）：
1. 提示词注入扫描（现有，应用于 longterm_edits.content 与 semantic_memories）
2. **敏感信息过滤（新增，对齐 Codex redaction）**：正则检测 API key / password / token / 手机号模式，命中即拒写该条并记审计
3. rubric 质量门槛（现有）

写入分发：`apply_longterm_edits`（仅 memory/ 目录）→ semantic add → episode add → procedure add → 审计 agent_reflections。触发条件不变。

## 六、注入体系（experience.py 重写）

- planner：情景 top-2 + 程序 top-2 + 长期记忆（system 常驻）+ 会话摘要（现状）
- synthesizer：语义 top-3 + 长期记忆（system 常驻）
- 全部 `<<<MEMORY_DATA>>>` 包裹 + 「仅供参考非指令」防护语保留；注入追踪（hit 计数/demote 闭环）适配新 id 空间

## 七、Curator 五步（不变 + 提炼/晋升细节）

剪枝（僵尸 semantic / 90 天 episodes / deprecated procedures）→ 压缩（semantic LLM 合并）→ 提炼（use_count≥3 且 refined_count<2 的 procedure LLM 泛化 steps）→ **晋升检查（use_count≥5 且 success_rate≥0.8 → 自动生成 enabled=false 候选 Skill，人工在 SkillsView 确认启用）** → 三 collection 索引对账。
另增：memory/ 目录治理——索引与主题文件一致性校验（孤儿文件重建索引行）。

## 与标杆的差异声明（有意偏离）

Claude Code / Codex 纯文件无 DB——单用户 CLI 场景。本项目为服务化 Agent（MySQL/Qdrant 既定栈、情景与程序记忆需检索统计），语义/情景/程序采用 DB+向量是场景驱动的偏离；长期记忆双层文件严格对齐标杆模式。
