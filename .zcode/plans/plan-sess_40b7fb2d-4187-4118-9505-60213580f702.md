## 文档结构

1. **背景**：本项目现有压缩机制概述（compact_history 的 LLM 合并摘要 + planner 800 字工具摘要 + KV Cache 兼容性）及其局限（有损、信息丢失）—— 作为调研动机
2. **六大范式调研**（每节含机制、代表工作、适用场景、失败模式、对本项目的适用性结论）：
   - Token 级提示压缩：LLMLingua / LLMLingua-2（20x、~1.5% 损失；只适用静态内容；不引入）
   - 语义压缩 Compaction：Anthropic 官方 compaction、Claude Code /compact 的 8 段结构化摘要 + 上下文恢复 + 多层压缩；失败模式（压缩循环 / context drift / 65% 失败归因 drift）
   - 折叠-可恢复：Context-Folding（arXiv 2510.11967，ICML 2026）branch-then-fold + unfold，~10x；FoldAct / AgentFold 后续
   - 记忆分层：MemGPT → Letta memory blocks、Mem0（"context window 是 RAM"）
   - 文件化持久 + 按需加载：Claude Code agentic memory、MEMORY.md 规范（frontmatter 分型、索引上限）
   - 结构性编辑：Anthropic context editing / tool result clearing（provider 依赖，DeepSeek 无）
3. **对本项目"按需加载"提案的印证**：提案 = 折叠可恢复 × 文件化的组合；与 Context-Folding 核心结论的对应关系；无需 RL 训练的工程化替代（预算阈值触发 + 向量匹配还原）
4. **对后续设计的三点修正建议**：结构化摘要字段（学 Claude Code，而非散文摘要）、摘要生成异步化（防压缩循环）、还原优先于压缩率（阈值放宽）
